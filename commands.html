Every command, ready to copy

All commands and Copilot prompts from the workshop, in chapter order. Select Copy, paste, press Enter. The same blocks sit inside each step, next to its screenshots.

How to use this page

Codespace terminal

Most commands run in the codespace you open in Chapter 2. Open the terminal with Ctrl+`. If VS Code asks you to confirm a multi-line paste, choose Paste.

Copilot CLI

Purple blocks are prompts. Start copilot in the codespace terminal, paste the prompt and press Enter. Copilot asks before every action it takes.

Your terminal

Blocks labelled Your terminal are optional alternatives to clicks in Settings and Security. They need your own sign-in: see below.

No editing needed. Commands use {owner} and {repo}, which the GitHub CLI fills in from the repository you are in. Working outside your clone? Point the GitHub CLI at your repository once per terminal:
>_Your terminal (GitHub CLI)Once per terminal
export GH_REPO="$(gh api user --jq .login)/contoso-company-profile"

Your terminal: sign in with your own account

Commands labelled Your terminal change repository settings or read security alerts. The codespace's built-in token is scoped for working on this one repository and does not cover settings or security alerts, so run them where you signed in with your own account. Every one of them also has a click path in its step.

>_Your laptop
gh auth login
gh repo clone "$(gh api user --jq .login)/contoso-company-profile"
cd contoso-company-profile

Skip the clone if you created the repository with the commands in step 1.1.

>_Second codespace terminal
unset GITHUB_TOKEN
gh auth login

Open it with + in the terminal panel and use it only for these commands. Git in the codespace signs in with the codespace token, so keep your first terminal for everything else.

Teams can instead add a fine-grained personal access token as a Codespaces secret named GH_TOKEN; the GitHub CLI uses it by default (GitHub Docs).

Chapter 1 · Prepare the GitHub repo

1.1Create your repository from the starter templateOpen the step →

>_Your terminal (GitHub CLI)Optional
gh auth status || gh auth login
gh repo create contoso-company-profile --public \
  --template ibranibeny/contoso-company-profile-starter --clone
cd contoso-company-profile

Same result as the clicks above, from any terminal with the GitHub CLI. gh auth login only runs if you are not signed in yet.

1.2Look around your new repositoryOpen the step →

>_Your terminal (GitHub CLI)Optional
git log --oneline
ls -a
cat .github/copilot-instructions.md

Inside the clone from step 1.1: one Initial commit, the files, and the house rules Copilot follows.

1.3Switch on GitHub Pages with GitHub ActionsOpen the step →

>_Your terminal (GitHub CLI)Optional
gh api -X POST "repos/{owner}/{repo}/pages" -f build_type=workflow

Optional. It changes a repository setting, which the codespace's built-in token cannot do, so run it where you signed in with your own account (how). If Pages is already on, use -X PUT instead of -X POST to switch the source.

1.4Run the deploymentOpen the step →

>_Your terminal (GitHub CLI)Optional
gh workflow run deploy-pages.yml
sleep 5
gh run watch "$(gh run list --workflow deploy-pages.yml --limit 1 --json databaseId --jq '.[0].databaseId')"

Starts the deployment, then follows the newest Deploy to GitHub Pages run until both jobs finish.

1.5Check the live siteOpen the step →

>_Your terminal (GitHub CLI)Optional
gh api "repos/{owner}/{repo}/pages" --jq .html_url

Prints the address of your live site.

Chapter 2 · Agentic SDLC in a codespace

2.1Start a codespace on mainOpen the step →

>_Your terminal (GitHub CLI)Optional
gh codespace create --repo "$(gh api user --jq .login)/contoso-company-profile" --branch main
gh codespace code --web

Creates the codespace and opens it in VS Code for the Web. If asked for a machine type, 2 cores is enough.

2.2Run the testsOpen the step →

>_Codespace terminal
node --version
gh --version
npm test

Open the terminal with Ctrl+`. If VS Code asks you to confirm a multi-line paste, choose Paste. Expected: every test passes.

2.3Install the GitHub Agentic Workflows CLIOpen the step →

>_Codespace terminal
gh extension install github/gh-aw \
  || curl -sL https://raw.githubusercontent.com/github/gh-aw/main/install-gh-aw.sh | bash
gh aw version

One paste for everyone. If GitHub refuses the extension install with HTTP 403: Resource protected by organization SAML enforcement, the second line runs gh-aw's official install script instead. Expected: gh aw version prints a version (v1.2.2 in our run).

2.4Initialise the repository for agentic workflowsOpen the step →

>_Codespace terminal
gh aw init
git status --short

Expected: new files under .github/, plus .vscode/settings.json and .gitattributes.

2.5Start the GitHub Copilot CLIOpen the step →

>_Codespace terminal
npm install -g @github/copilot
copilot

Sign in when Copilot CLI asks (type /login if it says you are not signed in).

✦Paste into Copilot CLI
Using the agentic-workflows skill, create a GitHub Agentic Workflow at .github/workflows/issue-triage.md for this repository. Trigger: when an issue is opened. The agent reads the issue, adds 1 to 3 labels from this list only: bug, enhancement, documentation, question, content, design, security (create missing labels), and posts ONE friendly comment that restates the request, proposes acceptance criteria and names the files under src/ that will probably change. Use the copilot engine, read-only permissions, GitHub tools for issues and labels, safe-outputs add-labels and add-comment only, and a 10 minute timeout. Then run gh aw compile and fix any errors until it compiles.

Paste it at the Copilot CLI prompt and press Enter.

2.7Review the generated workflow, then compile itOpen the step →

>_Codespace terminalOptional
gh aw compile
git status --short

Copilot runs the compile for you. Run it yourself after any edit to the Markdown workflow; never edit the .lock.yml by hand.

2.8Check least privilege, then commit and pushOpen the step →

✦Paste into Copilot CLI
Show me the frontmatter of .github/workflows/issue-triage.md, then commit all changes on main with the message "Add agentic issue triage workflow" and push to origin.
>_Codespace terminalCheck
sed -n '1,/^---$/p' .github/workflows/issue-triage.md

Prints only the frontmatter, so you can check permissions, tools and safe-outputs yourself. Run it in a second terminal (+ in the terminal panel).

2.9Let the agent use the built-in GITHUB_TOKENOpen the step →

✦Paste into Copilot CLI
This is a personal repository without a COPILOT_GITHUB_TOKEN secret. Update .github/workflows/issue-triage.md so the Copilot engine uses the built-in GITHUB_TOKEN by adding the copilot-requests: write permission, recompile it, then commit with the message "Use GITHUB_TOKEN for Copilot requests" and push to origin main.
>_Codespace terminalCheck
grep -n 'copilot-requests' .github/workflows/issue-triage.md
git log --oneline -3

Expected: the permission line, and your two commits on top of the template.

2.11Watch the agentic workflow runOpen the step →

>_Codespace terminal
gh run list --workflow issue-triage.lock.yml --limit 3
gh run watch "$(gh run list --workflow issue-triage.lock.yml --limit 1 --json databaseId --jq '.[0].databaseId')"

Lists the latest Issue triage runs, then follows the newest one until it finishes. It can sit in Queued for a few minutes first.

2.12Read the triage resultOpen the step →

>_Codespace terminal
gh issue view 1 --comments

Expected: labels from the allowed list and one comment from github-actions.

Chapter 3 · Build with Copilot Fusion

✦Copilot CLI
/model

Choose Copilot Fusion in the list, then the Standard effort level.

>_Codespace terminalOr start a new session
copilot --model fusion

Starts Copilot CLI with Copilot Fusion selected (model name fusion).

3.2Hand the issue to CopilotOpen the step →

✦Paste into Copilot CLI
Read issue #1 and the triage comment on it. Create a branch feature/careers-page and implement the Careers page it describes: add it to the main navigation, keep all content in src/data/careers.json, reuse the existing design system, use fictional Contoso data only and extend test/site.test.mjs so the new page is checked. Run npm test until it passes, then commit, push the branch and open a pull request that closes #1.

3.3Watch Fusion work, approve as it goesOpen the step →

>_Codespace terminalCheck

npm test

In a second terminal while Copilot works, or after it finishes.

3.4Preview the Careers page in the codespaceOpen the step →

>_Codespace terminal
npm run build && npm run serve

Then open the Ports tab and select the globe icon next to port 8080. Press Ctrl+C to stop the preview.

Only if Copilot did not push the branch and open the pull request itself.

Chapter 4 · Copilot code review

4.1Request a review from CopilotOpen the step →

>_Codespace terminalOptional
gh pr edit --add-reviewer @copilot

On the feature/careers-page branch; same as choosing Copilot under Reviewers. Needs GitHub CLI 2.88 or later (the codespace in our run had 2.103).

>_Codespace terminalOlder GitHub CLI
gh api -X POST "repos/{owner}/{repo}/pulls/$(gh pr view --json number --jq .number)/copilot-code-review"

The same request through the REST API. HTTP 409 means a Copilot review is already pending.

4.2Read Copilot's reviewOpen the step →

>_Codespace terminalOptional
gh pr view --comments
gh api "repos/{owner}/{repo}/pulls/$(gh pr view --json number --jq .number)/comments" \
  --jq '.[] | "\(.path):\(.line // .original_line)  \(.body)"'

The summary review, then each inline comment as file:line comment.

4.3Act on the commentsOpen the step →

✦Paste into Copilot CLI
Read the Copilot code review comments on the pull request for this branch. Fix each valid finding, tell me which ones you would not change and why, run npm test until it passes, then commit and push to the same branch.
>_Codespace terminalRe-request review
gh api -X POST "repos/{owner}/{repo}/pulls/$(gh pr view --json number --jq .number)/copilot-code-review"

After the fixes are pushed, asks Copilot for a fresh review. HTTP 409 means one is already pending.

4.4Make Copilot review automatic with a rulesetOpen the step →

>_Your terminal (GitHub CLI)Optional
gh api -X POST "repos/{owner}/{repo}/rulesets" --input - <<'EOF'
{
  "name": "main-review",
  "target": "branch",
  "enforcement": "active",
  "conditions": { "ref_name": { "include": ["~DEFAULT_BRANCH"], "exclude": [] } },
  "rules": [
    { "type": "copilot_code_review",
      "parameters": { "review_on_push": true, "review_draft_pull_requests": false } }
  ]
}
EOF

Optional. It changes a repository setting, which the codespace's built-in token cannot do, so run it where you signed in with your own account (how).

4.5Merge and ship the Careers pageOpen the step →

>_Codespace terminal
gh pr merge --squash --delete-branch
gh issue view 1 --json state --jq .state
sleep 10
gh run watch "$(gh run list --workflow deploy-pages.yml --limit 1 --json databaseId --jq '.[0].databaseId')"

Expected: CLOSED for issue #1, then the deployment that ships the Careers page.

Chapter 5 · Code security

5.1Turn on CodeQL default setupOpen the step →

>_Your terminal (GitHub CLI)Optional
gh api -X PATCH "repos/{owner}/{repo}/code-scanning/default-setup" -f state=configured
gh api "repos/{owner}/{repo}/code-scanning/default-setup" --jq '{state, languages}'

Optional. It changes a repository setting, which the codespace's built-in token cannot do, so run it where you signed in with your own account (how).

5.2Find the vulnerabilityOpen the step →

>_Your terminal (GitHub CLI)Optional
gh api "repos/{owner}/{repo}/code-scanning/alerts?state=open" \
  --jq '.[] | [.number, .rule.id, .most_recent_instance.location.path] | @tsv'

Optional. It reads security alerts, which the codespace's built-in token cannot do, so run it where you signed in with your own account (how). Expected: a cross-site scripting alert in src/assets/js/news-search.js.

5.3Generate a fix with Copilot AutofixOpen the step →

>_Your terminal (GitHub CLI)Optional · REST API
ALERT=$(gh api "repos/{owner}/{repo}/code-scanning/alerts?state=open" \
  --jq '[.[] | select(.most_recent_instance.location.path == "src/assets/js/news-search.js")][0].number')
echo "Alert: $ALERT"
gh api -X POST "repos/{owner}/{repo}/code-scanning/alerts/$ALERT/autofix"
sleep 30
gh api "repos/{owner}/{repo}/code-scanning/alerts/$ALERT/autofix" --jq '.status, .description'

Asks Copilot Autofix for a fix. Re-run the last line until the status is success.

>_Your terminal (GitHub CLI)Optional · REST API
gh api -X POST "repos/{owner}/{repo}/git/refs" -f ref=refs/heads/fix/newsroom-xss \
  -f sha="$(gh api "repos/{owner}/{repo}/git/ref/heads/main" --jq .object.sha)"
gh api -X POST "repos/{owner}/{repo}/code-scanning/alerts/$ALERT/autofix/commits" \
  -f target_ref=refs/heads/fix/newsroom-xss -f message="Fix XSS in newsroom search (Copilot Autofix)"
gh pr create --base main --head fix/newsroom-xss \
  --title "Fix XSS in newsroom search" --body "Copilot Autofix for code scanning alert #$ALERT"

Commits the fix to a new branch and opens the pull request. Same terminal, so $ALERT is still set.

5.4Merge the fix and close the alertOpen the step →

>_Your terminal (GitHub CLI)Optional
gh pr merge fix/newsroom-xss --squash --delete-branch
gh api "repos/{owner}/{repo}/code-scanning/alerts?state=fixed" --jq '.[] | [.number, .rule.id, .state] | @tsv'

Only if you used the REST commands in 5.3; otherwise merge the Autofix pull request in the browser. The alert shows as fixed after the next analysis on main.

5.5See push protection stop a secretOpen the step →

>_Codespace terminalOptional · command line
read -rsp "Paste the dummy token from the GitHub Docs tutorial, then press Enter: " TOKEN; echo
git switch -c test/push-protection
printf '%s\n' "$TOKEN" > secret-test.txt
git add secret-test.txt
git commit -m "Test push protection"
git push -u origin test/push-protection

Expected: GitHub rejects the push because it contains a secret. Do not bypass.

>_Codespace terminalClean up
git switch main
git branch -D test/push-protection
unset TOKEN

Deletes the test branch and its blocked commit. Nothing reached GitHub.

Chapter 6 · Dependabot

>_Your terminal (GitHub CLI)Optional

gh api -X PUT "repos/{owner}/{repo}/automated-security-fixes"
gh api "repos/{owner}/{repo}/automated-security-fixes"

Optional. It changes a repository setting, which the codespace's built-in token cannot do, so run it where you signed in with your own account (how). Expected last line: "enabled":true.

6.2Read the alertsOpen the step →

>_Your terminal (GitHub CLI)Optional
gh api "repos/{owner}/{repo}/dependabot/alerts?state=open" \
  --jq '.[] | [.number, .security_advisory.severity, .dependency.package.name, .security_vulnerability.first_patched_version.identifier] | @tsv'

Optional. It reads security alerts, which the codespace's built-in token cannot do, so run it where you signed in with your own account (how).

6.3Merge Dependabot's security updateOpen the step →

>_Codespace terminalOptional
PR=$(gh pr list --app dependabot --search "ejs in:title" --json number --jq '.[0].number')
gh pr checks "$PR" --watch && gh pr merge "$PR" --squash --delete-branch

Finds Dependabot's ejs pull request, waits for CI and merges it.

6.4Add version updates for npm and GitHub ActionsOpen the step →

{ }New file · .github/dependabot.yml
version: 2
updates:
  - package-ecosystem: "npm"
    directory: "/"
    schedule:
      interval: "weekly"
    groups:
      npm-dependencies:
        patterns: ["*"]
  - package-ecosystem: "github-actions"
    directory: "/"
    schedule:
      interval: "weekly"
    groups:
      github-actions:
        patterns: ["*"]

In the browser: Add file → Create new file, name it .github/dependabot.yml, paste and commit to main.

>_Codespace terminalOr in the terminal
git switch main && git pull
mkdir -p .github
cat > .github/dependabot.yml <<'EOF'
version: 2
updates:
  - package-ecosystem: "npm"
    directory: "/"
    schedule:
      interval: "weekly"
    groups:
      npm-dependencies:
        patterns: ["*"]
  - package-ecosystem: "github-actions"
    directory: "/"
    schedule:
      interval: "weekly"
    groups:
      github-actions:
        patterns: ["*"]
EOF
git add .github/dependabot.yml
git commit -m "Add Dependabot version updates"
git push origin main

Writes the same file, commits it and pushes to main.

6.5Merge the GitHub Actions updateOpen the step →

>_Codespace terminalOptional
gh pr list --app dependabot
PR=$(gh pr list --app dependabot --search "github-actions in:title" --json number --jq '.[0].number')
gh pr checks "$PR" --watch && gh pr merge "$PR" --squash --delete-branch

Dependabot needs a few minutes after the push in 6.4 to open its grouped pull requests.
